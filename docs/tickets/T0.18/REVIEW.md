# T0.18: Review note

**Verdict:** ✅ Approved · **Branch:** `feature/tickets`

## What changed

- `platform` serves its OpenAPI document, generated by FastAPI from its code. The same document is committed at `backend/services/platform/openapi.json`, written by `.github/scripts/export_openapi.py`. The service still has no command line (D406).
- The contract check is the service's own pytest suite `tests/contracts/`. It fails when the committed document differs from the served one (JSON equality). When `ERP_CONTRACT_BASELINE` is set, it also fails when the base document loses a path, an operation, a parameter, a schema or a property, or a `type`/`$ref` changes. Additions pass.
- CI: a "Contract check" step in the `services` job of `python.yml` runs `check_contract.sh` with the PR base SHA or the push's `before`. With no base document, only the stale check runs. The services checkout is now full depth.
- The comparator, service, repository and models are layered inside `erp_platform`. Moving them to `backend/shared/` when a second service publishes an OpenAPI is a recorded follow-up.
- Plan change (K16/K17): the platform runtime image now runs `apt-get upgrade` and uninstalls the system pip before `USER`, so that CI's Trivy scan of #894 passes. A Dockerfile text test guards this.

## Look at first

- **The CI contract step:** `.github/scripts/check_contract.sh` and `.github/workflows/python.yml` (services job). Event values reach the step only through `env`, and the base SHA is checked with `git cat-file` before use. The baseline file is a temporary file removed on exit.
- **The breaking-change rules:** `backend/services/platform/src/erp_platform/service/contracts/contract_comparator.py`. It compares only `type`/`$ref`, and recurses only through `properties`/`items`. This is enough for the criteria, but the gaps are known follow-ups.
- **The image hardening:** `backend/services/platform/Dockerfile` lines 20-24, and `tests/image/test_dockerfile.py`. With the GHA layer cache, the upgrade layer is reused until the base image changes (follow-up).
- **Company data isolation:** none at stake. The ticket reads no company data. `/openapi.json` sits behind the company context (it is not in `public_paths`), which is why the contract-test client sends the context headers. The token in the conftest is a test fixture, not a secret.
