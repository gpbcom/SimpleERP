# T0.09: Company context and rights middleware

**Status:** ✅ Done · **Ticket:** [TICKET.md](TICKET.md) · **Choices and trade-offs:** [IMPLEMENTATION.md](IMPLEMENTATION.md) · **Review:** [REVIEW.md](REVIEW.md)

## 🔭 What it does

- A new shared library, `erp_context`, refuses every HTTP request that names no valid company or no user, and binds the company, the user and the request id for the rest of the request.
- One decision path answers "may this user do this action on this record?", from a direct call and from HTTP alike. A record of another company is refused, a deny wins, and with no allowing policy the answer is no.
- Every refusal is answered as `application/problem+json` with its code, built from a catalogue, and is logged at WARNING with who, what and why.

## ⚙️ How it works

1. **Configuration:** [`ContextConfig`](../../../backend/shared/context/src/erp_context/models/context/context_config.py) holds the three header names and the public paths, which are empty by default.
2. **Request entry:** [`CompanyContextMiddleware.__call__`](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L152) is a pure ASGI class. Lifespan calls pass; websockets are closed with code 1008 ([line 42](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L42), [lines 164-169](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L164-L169)); public paths pass by exact match ([line 170](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L170)).
3. **Reading the headers:** the request id comes from its header or a generated uuid ([line 176](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L176)). An absent or invalid company becomes `SEAccessNoCompanyError` ([lines 97-116](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L97-L116)); an absent user becomes `SEAccessNoUserError` ([line 181](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L181)).
4. **Refusal at the door:** [`_refuse`](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L118) logs the refusal at WARNING and answers the problem+json without calling the application.
5. **Binding:** a valid request gets a `RequestContext`, bound through [`CompanyContextService.bind`](../../../backend/shared/context/src/erp_context/service/context/company_context_service.py#L42) into a `ContextVar` held in [`RequestContextStore`](../../../backend/shared/context/src/erp_context/storage/context/request_context_store.py#L24). The token is released in a `finally` ([lines 190-192](../../../backend/shared/context/src/erp_context/api/middleware/company_context_middleware.py#L190-L192)).
6. **Asking for a right:** [`RightsService.decide`](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L80) refuses first a record of another company ([line 91](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L91)), then asks every [`Policy.vote`](../../../backend/shared/context/src/erp_context/service/rights/policy.py#L25). One DENY refuses ([line 103](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L103)), an ALLOW grants ([line 113](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L113)), and otherwise the deny-by-default `no-policy` applies ([line 114](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L114)). Each refusal is logged in [`_refuse`](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L51).
7. **Two entrances, one path:** [`allowed`](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L116) returns a bool for a direct call. [`enforce`](../../../backend/shared/context/src/erp_context/service/rights/rights_service.py#L129) raises `SEAccessDeniedError`, and [`RightsGuard.check`](../../../backend/shared/context/src/erp_context/api/rights/rights_guard.py#L42) calls it for the current user.
8. **The answer:** [`RefusalHandler.__call__`](../../../backend/shared/context/src/erp_context/api/problems/refusal_handler.py#L48) reads the request id from the context and asks [`ProblemBuilder.build`](../../../backend/shared/context/src/erp_context/api/problems/problem_builder.py#L39), which fills the body from the catalogue entry only ([lines 51-59](../../../backend/shared/context/src/erp_context/api/problems/problem_builder.py#L51-L59)). The entries are data in [`refusal_codes.yaml`](../../../backend/shared/context/conf/catalogs/refusal_codes.yaml). [`ProblemResponse`](../../../backend/shared/context/src/erp_context/api/problems/problem_response.py) sends it as problem+json.
