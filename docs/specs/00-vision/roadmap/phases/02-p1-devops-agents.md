# 🛣️ P1: DevOps agents

**Status:** ✅ specified (D569) · **Sprints:** S05 to S07 · **Dates:** 15 Feb to 26 Mar 2027 · **Tickets:** 36

> [!NOTE]
> P1 builds the factory first: the DevOps agents of F25 run in GitHub Actions on isolated European runners, a team of agent roles turns an approved ticket into a verified draft pull request that a maintainer reviews and merges, and the closed hosted service around them takes customers' requests, triages them and tells the customer, so that every later phase is built with them ([D483](../../../06-decisions/vision/d483-roadmap-devops-agents-first.md), [D437](../../../06-decisions/f25-devops-agents/d437-devops-agents-in-the-ci.md), [D567](../../../06-decisions/f25-devops-agents/d567-the-agent-team-roles-contract-worktrees-one-commit-verification.md)).

## <a id="goal"></a>🎯 Goal

At the end of P0 the repository has its layout ([D438](../../../06-decisions/technical/d438-repository-layout.md)), its shared kit and its pipeline, and the Claude Code harness of `.claude/` builds roadmap tickets on a laptop: a planner writes a task graph with file ownership, test writers and implementers work in their own worktrees, an integrator applies their work, a verifier runs the checks, a read-only reviewer approves, and the person approves the plan and the push (`.claude/rules/tickets.md`, TKT-3 to TKT-6, TKT-18). P1 moves that factory into the CI and puts the closed hosted service of F25 around it.

- **The agents live in the CI** ([D437](../../../06-decisions/f25-devops-agents/d437-devops-agents-in-the-ci.md)): GitHub Actions workflows run the Claude Code GitHub Action, which is the Claude Code harness, so the agents read this repository's `CLAUDE.md` and `.claude/` and follow the same rules as people. The runners are ephemeral pods of Actions Runner Controller in a separate, isolated European cluster with no outbound access except GitHub and the AI gateway, and never run jobs from forks or outside pull requests ([D442](../../../06-decisions/f25-devops-agents/d442-devops-runners-isolated-cluster.md), [D375](../../../06-decisions/vision/d375-managed-hosting-eu-only.md), [D421](../../../06-decisions/technical/d421-infrastructure-cncf.md)).
- **The agent team builds on the harness, it does not duplicate it.** ([D567](../../../06-decisions/f25-devops-agents/d567-the-agent-team-roles-contract-worktrees-one-commit-verification.md)) The six roles of [FL-F25-08](../../../02-functional/f25-devops-agents/flows/fl-f25-08-team-builds-a-ticket.md) are the agents `.claude/agents/` already holds: the architect is the `planner` (its task graph with file ownership becomes the work contract [E-F25-19](../../../02-functional/f25-devops-agents/data/e-f25-19-work-contract.md)), the backend and frontend engineers are `implementer` and `frontend-implementer`, the test engineer is `test-writer` then `verifier`, the code reviewer is `reviewer` (read only), the release engineer is `integrator`. P1 adds what F25 asks beyond the laptop harness: the run in Actions, commits in each handoff instead of uncommitted patches ([BR-F25-25](../../../02-functional/f25-devops-agents/business-rules/br-f25-25-a-handoff-without-its-commits-and-checks-is-refused.md)), one active run per repository instead of several tickets at once ([BR-F25-30](../../../02-functional/f25-devops-agents/business-rules/br-f25-30-one-active-run-per-repository-resumed-from-its-checkpoint.md)), checkpoints kept on GitHub, and a draft pull request that the agents never merge ([BR-F25-05](../../../02-functional/f25-devops-agents/business-rules/br-f25-05-agents-never-merge-or-deploy.md)).
- **Nothing reaches Ready, `develop` or production without a maintainer** ([D434](../../../06-decisions/f25-devops-agents/d434-maintainer-approval-label.md), [D441](../../../06-decisions/f25-devops-agents/d441-approval-label-reported-and-reverted.md)): the `needs-maintainer-approval` label keeps agent-created issues in Backlog, a workflow reports and reverts any removal by someone else, branch protection requires a maintainer's review, and the agents' GitHub App cannot approve or merge.
- **Customers' requests become USER features** ([D433](../../../06-decisions/f25-devops-agents/d433-user-family-and-labels.md)): the closed intake service files a sanitised USER feature with one ticket, the agents deduplicate and triage it, study the specs and the code for a feature and draft the spec pull request, or reproduce a bug read-only on a masked copy and propose the fix tests first; the customer follows the request in plain words.
- **Where the code lives.** F25 is a closed service of the hosted edition ([D388](../../../06-decisions/vision/d388-hosted-edition-open-core.md), [D447](../../../06-decisions/vision/d447-country-pack-updates-free-hosted-only-named.md)). In this repository: the agents' workflows in `.github/` (the layout names "the DevOps agents' workflows (D437)") and the agent roles and skills in `.claude/`. Outside it, in a separate private repository ([D415](../../../06-decisions/technical/d415-supply-chain-controls.md), [repository layout](../../../../technical/architecture/repository-layout.md): "Outside this repository: the closed hosted services"), laid out like this one: the intake service, the masked copy's read-only MCP server, the console and its data. In the ticket graph, `backend/services/devops` and `frontend/devops` name the folders of that private repository; the isolated runners' cluster is declared in the private GitOps repository of the hosted clusters ([D420](../../../06-decisions/technical/d420-devops-practice.md)) with `infra/terraform` and `infra/helm`. The closed code links and copies no AGPL code: it reaches SimpleERP only through its public API and MCP ([D388](../../../06-decisions/vision/d388-hosted-edition-open-core.md)), and its CI checks it ([supply chain and licences](../../../../technical/security/supply-chain-and-licences.md)).

## <a id="exit"></a>🚪 Exit criteria

- [ ] An agent team turns an approved ticket of P2 into a draft pull request that passes CI, carries its evidence and gets a maintainer's review; its runners run in the isolated European cluster ([D442](../../../06-decisions/f25-devops-agents/d442-devops-runners-isolated-cluster.md), [FL-F25-08](../../../02-functional/f25-devops-agents/flows/fl-f25-08-team-builds-a-ticket.md), the roadmap's step 1).
- [ ] No agent can merge, deploy, set Ready or remove `needs-maintainer-approval`: each is tried in a test and refused or reverted ([BR-F25-05](../../../02-functional/f25-devops-agents/business-rules/br-f25-05-agents-never-merge-or-deploy.md), [BR-F25-07](../../../02-functional/f25-devops-agents/business-rules/br-f25-07-approval-before-ready.md), [D441](../../../06-decisions/f25-devops-agents/d441-approval-label-reported-and-reverted.md), [REQ-T06-07](../../../03-technical/t06-mcp-and-a2a-gateway/requirements/req-t06-07-github-tools.md)).
- [ ] A runner pod reaches only GitHub and the AI gateway (or, until T7, the listed provider), and no job from a fork runs on it ([D442](../../../06-decisions/f25-devops-agents/d442-devops-runners-isolated-cluster.md)).
- [ ] Every agent run is recorded with what it read, what it wrote and its cost, and stops on its turns, its 30 minutes or its budget ([BR-F25-11](../../../02-functional/f25-devops-agents/business-rules/br-f25-11-agents-metered-and-audited.md), [BR-F25-30](../../../02-functional/f25-devops-agents/business-rules/br-f25-30-one-active-run-per-repository-resumed-from-its-checkpoint.md), [D398](../../../06-decisions/f22-unified-cost-management/d398-budgets-warn-then-stop.md)).
